# ADR-0001: 네이티브 iOS vertical slice

- 상태: Accepted
- 결정일: 2026-08-09
- 범위: 최초 플레이 가능한 제품 검증판

## 맥락

한 손 세로 플레이, 짧은 세션, 한국어 UI, 즉각적인 터치·애니메이션 반응이 필요한 캐주얼 게임이다. 팀은 출시 가능성을 검증하면서도 초기 SDK·서버·운영 복잡도를 제한해야 한다. 핵심 규칙은 빠르게 반복 테스트할 수 있어야 한다.

## 결정

1. iOS 17 이상, iPhone 전용 네이티브 앱으로 만든다.
2. 앱 셸과 화면은 SwiftUI, 프레임 기반 게임 보드는 SpriteKit을 사용한다.
3. 화면/실행 조정은 `@MainActor AppModel`, 결정론적 규칙은 Foundation 기반 순수 Swift로 분리한다.
4. 게임 규칙은 SwiftPM에서도 빌드해 빠르게 테스트하되 App Store 산출물의 권위는 Xcode 프로젝트로 둔다.
5. 프로필은 버전이 있는 JSON으로 UserDefaults에 로컬 저장한다.
6. 서버, 광고, 분석, 계정과 외부 SDK는 vertical slice에서 제외한다. core 재미·retention Gate 전에는 수익화 경계를 제품 흐름에 노출하지 않는다.

## 선택 이유

- SwiftUI는 홈/설정/결과와 접근성 트리를 빠르게 구성한다.
- SpriteKit은 장면 루프, 터치, 파티클, 노드 애니메이션에 적합하며 Apple 플랫폼 배포 경계를 단순하게 한다.
- 순수 Swift 규칙은 렌더러 없이 seed 기반 회귀 테스트가 가능하다.
- 서버·SDK 제외는 최초 슬라이스의 개인정보, 장애, 공급망 리스크를 줄인다.

## 검토한 대안

| 대안 | 보류 이유 |
|---|---|
| 전체 SwiftUI/Canvas | 프레임 상태와 충돌·노드 애니메이션 관리가 게임 복잡도 증가 시 불리함 |
| Unity 등 범용 엔진 | 다중 플랫폼 계획이 없고 바이너리·빌드·SDK 표면이 현재 가치보다 큼 |
| 웹 래퍼 | 촉감, 프레임 일관성, App Store 네이티브 품질 목표에 불리함 |
| 초기 백엔드/계정 | 현재 핵심 루프 검증에 필요하지 않고 개인정보·운영 부담을 선행시킴 |

## 결과

긍정적 결과:

- 외부 의존성 없이 재현 가능한 작은 빌드 표면을 갖는다.
- 규칙과 렌더링을 분리해 게임 밸런스 테스트가 빠르다.
- 게임 규칙과 시각 MVP를 외부 서비스 실패 없이 독립 검증할 수 있다.

비용과 제약:

- SwiftPM 통과만으로 iOS 앱 컴파일·리소스·서명을 보장하지 않는다.
- SwiftUI와 SpriteKit 사이의 lifecycle/state 경계를 별도로 테스트해야 한다.
- iOS 외 플랫폼 재사용은 규칙 계층에 한정된다.
- 로컬 전용 데이터는 기기 변경·삭제 시 복구되지 않는다.

## 재검토 조건

Android 동시 출시, 계정/동기화, 서버 권위 점수, 실시간 이벤트, 실제 광고·분석 SDK, 원격 구성, 앱 클립 중 하나를 승인할 때 이 ADR을 대체하거나 후속 ADR을 작성한다.
