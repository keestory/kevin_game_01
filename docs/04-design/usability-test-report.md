# Usability Test Report — 계획 / 미실행

> 상태: **NOT RUN — 결과 없음**
> 문서 목적: 최소 5명 테스트 계획과 Gate 기준 고정
> 현재 단계: Stage 0/1 재검증
> 테스트 완료 전 UX/Product Gate 통과 금지

## 1. Executive Summary

실제 사용자 테스트는 아직 한 건도 수행하지 않았다. 아래 수치와 표는 결과가 아니라 사전 등록된 계획이다. 빈 결과를 성공처럼 해석하거나 기존 UI 테스트를 사용자 연구로 대체하지 않는다.

## 2. 연구 질문

1. 첫 사용자가 설명 없이 시작 행동과 탭 규칙을 이해하는가.
2. 3명 연결, 환승객, 안전 손잡이의 의미를 구분하는가.
3. 첫 실패와 혼잡 완화를 공정하고 회복 가능하게 느끼는가.
4. 구조 광고의 비용·보상·거절 결과를 오해하지 않는가.
5. 텍스트 공유와 실제 같은 시드 도전의 차이를 이해하는가.
6. Larger Text, VoiceOver, Reduce Motion 환경에서 핵심 과업이 가능한가.

## 3. 참여자 계획

Gate 최소 5명:

| Participant | 모집 조건 | 목적 |
|---|---|---|
| P01 | 주 3회 이상 모바일 퍼즐 플레이 | 장르 기대 비교 |
| P02 | 주 3회 이상 모바일 퍼즐 플레이 | 숙련자 난이도·재시도 |
| P03 | 캐주얼 게임 월 1~4회 | 초보 이해도 |
| P04 | Larger Text 또는 색각 보정 사용 경험 | 시각 접근성 |
| P05 | VoiceOver, Voice Control, Switch Control 중 하나의 실제 사용자 | 보조기술 핵심 과업 |

가능하면 연령·성별·iPhone 크기를 다양화한다. 직원·개발자·기획 참여자는 제외한다. P05 모집이 어려워도 비장애 참여자로 대체해 접근성 Gate를 통과시키지 않는다.

별도로 문제 반복성을 검증하는 JTBD 인터뷰 8~15명이 필요하며, 이 5명 사용성 테스트가 Problem Validation을 대신하지 않는다.

## 4. 방법

- 방식: 1:1 조정 사용성 테스트, 대면 또는 화면·손·음성 동시 녹화 원격 세션.
- 시간: 35~45분.
- 기기: 참가자 개인 iPhone 우선, 테스트 기기 보조.
- 빌드: 버전·rules version·시드를 기록한 TestFlight 빌드.
- 진행자: 유도 질문 금지, 과업 중 도움 요청 횟수 기록.
- 동의: 녹화·민감 접근성 정보 수집 범위와 보관 기간을 사전 안내.

### 세션 순서

1. 사전 질문 5분: 최근 플레이, 짧은 시간의 대안, 광고 경험.
2. 첫 실행 무설명 관찰 10분.
3. 실패·구조 프로토타입 7분.
4. 공유·친구 도전 클릭 프로토타입 5분.
5. 접근성 설정별 과업 8분.
6. 회고 인터뷰 5분.

## 6. 측정

- 과업 성공: 성공/부분/실패.
- 완료 시간.
- 오탭·되돌아감·잘못된 예측.
- 진행자 도움 횟수.
- 첫 실패 직후 감정과 이탈 의향.
- 광고 강제성 1~5점, 4~5 응답 비율.
- 규칙·보상 자유 회상.
- Single Ease Question(과업별 1~7).
- 세션 종료 후 재도전 의향과 이유.

표본 5명 결과는 방향성 발견용이며 퍼센트를 시장 전체로 일반화하지 않는다.

## 7. 사전 Gate 기준

### 필수 통과

- T01~T05 각각 4/5 이상 무도움 성공.
- T06은 5/5 정확한 이해. 광고 오선택은 1명도 허용하지 않음.
- T08은 해당 보조기술 사용자가 핵심 과업을 완료하거나, 완료하지 못하면 접근성 지원 주장을 제거하고 P1로 유지.
- P0 발견 0건, P1 발견 0건.
- 5명 모두 새 판이 광고·초대·가입 없이 무료임을 이해.

### 즉시 Fail

- 2명 이상이 첫 입력 또는 3명 연결을 이해하지 못함.
- 1명이라도 광고를 필수 결제로 오인하거나 거절 시 플레이가 막힌다고 생각함.
- 1명이라도 친구 설치·평점이 보상 조건이라고 오해함.
- 보조기술 사용자가 코어 과업에 진입하지 못함.
- 멀미, 광과민, 반복 진동으로 중단하는 사례 발생.
