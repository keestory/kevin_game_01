# Draft User Flows — 한 칸만! 만원열차

> 상태: DRAFT / 미승인
> 현재 단계: Stage 0/1 재검증
> 구현과 목표 흐름이 다를 때 둘을 분리해 적는다.

## 1. 정보 구조

```text
앱 실행
└─ 홈
   ├─ 현재 역 운행
   │  └─ 튜토리얼(첫 실행만)
   │     └─ 플레이
   │        ├─ 일시정지
   │        ├─ 안전 손잡이 복구
   │        ├─ 구조 제안
   │        │  ├─ 무료 구조
   │        │  ├─ 광고 구조
   │        │  └─ 결과로 이동
   │        └─ 결과
   │           ├─ 다음 역/재도전
   │           ├─ 기록 공유
   │           └─ 홈
   └─ 설정
```

`오늘의 막차`, 실제 친구 도전, 노선도·꾸미기는 현재 제품 이름 또는 후보일 뿐 독립 완성 흐름으로 구현·검증되지 않았다.

## 2. 첫 실행

### 현재 관측

```text
홈 → 운행 시작 → 정적 튜토리얼 오버레이 → “연습 없이 바로 출발” → 플레이
```

### 검증 목표

1. 앱 실행 5초 안에 주 행동이 보인다.
2. 계정·알림·추적 동의를 선행하지 않는다.
3. 튜토리얼은 `탭`, `3명 연결`, `안전 손잡이`만 설명한다.
4. 사용자가 문구를 읽지 않아도 첫 승객 배치가 가능해야 한다.
5. 튜토리얼 종료 직후 선택기가 갑자기 진행되지 않도록 3초 준비 상태를 검토한다.

### 실패/예외

- 튜토리얼 중 백그라운드: 복귀 후 계속 일시정지.
- Larger Text에서 내용이 잘림: 스크롤 또는 단계 분할.
- VoiceOver: 핵심 보드가 조작 불가능하면 지원 완료로 표시하지 않는다.

## 3. 코어 운행

```text
다음 승객 확인
→ 선택기 이동 관찰
→ 원하는 열에서 화면 탭
→ 승객 배치
→ 3명 이상 연결 시 하차
→ 점수·시간·손잡이 피드백
→ 목표 달성 또는 종료 조건
```

핵심 피드백은 시각, 텍스트, 햅틱 중 둘 이상으로 전달한다. 색만으로 목적지를 설명하지 않는다.

## 4. 안전 손잡이

```text
가득 찬 열에 배치 시도
→ 경고 햅틱·열 강조
→ 손잡이 남음?
   ├─ 예: 손잡이 1개 차감 → 상단 승객 하차 → 3초 감속 → 계속
   └─ 아니오: 구조 제안
```

수용 기준:

- 손잡이가 왜 줄었는지 한 번의 관찰로 이해 가능.
- 손잡이는 새 판 시작권이 아니라 현재 판의 오류 허용 횟수임을 설명.
- 손잡이 소진이 광고 시청을 강요하지 않음.

## 5. 반복 실패와 혼잡 완화

```text
같은 역 2회 연속 실패
→ 홈에 “혼잡 완화 운행” 표시
→ 목표·속도·환승객 변화 요약
→ 사용자가 다시 운행
→ 성공 시 일반 난이도로 복귀
```

숨은 조작으로 오해되지 않도록 상태를 공개한다. `쉬운 모드`처럼 낙인을 주는 명칭과 실패를 비난하는 문구를 피한다.

## 6. 구조 제안과 광고

### 생애 첫 구조

```text
실패 → 무료 구조임을 명시 → 수락/결과 보기 선택
```

### 이후 구조

```text
실패
→ “광고 1회 · 위 2줄 비우기 · +15초” 표시
→ 사용자가 선택
   ├─ 수락
   │  ├─ 활성 상태 광고 완료 callback → 보상 1회 → 계속
   │  ├─ 비활성 상태 광고 완료 callback → 해당 런의 pending 보상 보관
   │  │  → 복귀 후 “받은 보상으로 구조 계속” 선택 → 계속
   │  ├─ 광고 중 닫기 → 보상 없음 → 같은 제안 화면
   │  └─ 로딩/네트워크 실패 → 원인 문구 → 무료 새 판 가능
   └─ 거절 → 결과 → 즉시 무료 재도전
```

다크패턴 방지:

- 광고 CTA와 거절 CTA 모두 읽을 수 있는 대비와 터치 크기.
- 닫기·거절을 죄책감 문구로 표현하지 않음.
- 제안 화면에 가짜 타이머를 두지 않음.
- 광고를 본 기록을 공식 경쟁 기록과 섞지 않음.
- 이전 런의 늦은 callback은 현재 런에 적용하지 않음.
- 앱이 비활성인 동안 보상 callback이 와도 자동으로 게임을 재개하지 않음.

현재 모델 단위 테스트는 stale callback 무시와 비활성 pending 보상을 검증한다. 실제 광고 SDK의 중복·지연·중단 E2E는 미검증이다.

## 7. 결과와 재도전

```text
결과
├─ 완료: 실제 역 번호 + 기록 + 다음 역
└─ 실패: 원인 + 이전 대비 개선 + 같은 역 재도전
```

우선순위는 `재도전/다음 역` → `기록 공유` → `홈`이다. 공유가 진행을 막거나 보상 수령 조건이 되지 않는다.

현재 코드 감사에서는 성공 헤드라인이 실제 역 번호를 보간한다. 단, 결과 이해도와 다음 행동의 우선순위는 사용자 테스트 전 미검증이다.

## 8. 기록 공유와 친구 도전

### 현재 구현

시스템 ShareLink로 점수 텍스트만 공유한다. 링크, 초대 식별자, 동일 시드 진입, 완료 보상은 없다. 현재 사용자 문구는 `친구에게 기록 공유하기`로 기능과 일치하며 HomeView 내부 테스트 ID도 `shareRecordButton`으로 정리됐다.

### 후보 흐름 — 검증 후

```text
결과 → 친구에게 도전 보내기
→ 링크 수신
→ 앱 보유 여부
   ├─ 보유: 동일 시드 도전 준비
   └─ 미보유: App Store → 설치 → 15초 튜토리얼 → 도전 복귀
→ 60초 공식 기록 1회
→ 양쪽 최신 기록 비교
→ 양쪽에 동일한 비성능형 보상
→ 재대결
```

원칙:

- 설치·가입·평점에는 보상하지 않는다.
- 연락처 업로드를 요구하지 않는다.
- 친구 점수는 첫 공식 시도 전 숨기는 안을 테스트한다.
- Game Center 권장대로 개인 누적 최고가 아니라 해당 도전의 최신 기록을 우선 검토한다.
- 링크 만료, 앱 미설치 복귀, 오프라인, 이미 완료한 도전을 정의해야 한다.

## 9. 일시정지와 앱 수명주기

- 사용자의 일시정지: `계속 운행`, `홈` 제공.
- 백그라운드/전화/제어 센터: 자동 일시정지.
- 복귀: 즉시 진행하지 않고 사용자가 `계속 운행` 선택.
- 구조 광고 중 백그라운드: 광고 SDK callback이 확정되기 전 보상 금지.

## 10. 접근성 대체 흐름

- Reduce Motion: 배경 이동·지속 진동·입자·확대 축소를 줄인 정적 피드백.
- Larger Text: 홈·튜토리얼·결과·구조 화면은 스크롤 가능해야 함.
- 색각 다양성: 배지 도형과 이름을 함께 사용.
- VoiceOver/Voice Control: 현재 보드 단일 레이블만으로는 목표 열 선택이 어렵다. 별도 열 선택 컨트롤 또는 스캔 모드 검증 전 지원 완료로 표시하지 않는다.
- 시간 압박 접근성: 선택기 감속 또는 접근성용 단계 선택 방식을 사용자 테스트하되 경쟁 기록은 조건을 명확히 분리한다.

## 11. Flow Gate

다음 과업을 실제 사용자 5명 중 4명 이상이 도움 없이 완료하기 전에는 통과하지 않는다.

1. 첫 승객 배치
2. 3명 연결 규칙 설명
3. 실패 원인 확인과 재도전
4. 구조 보상과 거절 결과 설명
5. 설정에서 필요한 접근성 옵션 찾기
