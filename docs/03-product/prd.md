# Draft PRD — 한 칸만! 만원열차

> 상태: **DRAFT / 미승인 가설**
> 현재 단계: Stage 0 Brief + Stage 1 Market Discovery 재검증
> 기준일: 2026-08-09 (Asia/Seoul)
> 대상: 대한민국 iPhone, 한국어 우선
> 제품 상태: 검증 전 vertical slice. 이 문서는 이미 구현된 기능을 사후 승인하지 않는다.

## 1. Executive Summary

`한 칸만! 만원열차`는 움직이는 선택기에 맞춰 화면을 탭하고 같은 목적지 승객 3명 이상을 연결해 하차시키는 세로형 원터치 퍼즐이다. 현재 SwiftUI/SpriteKit vertical slice는 코어 규칙, 스테이지 난이도, 안전 손잡이, 구조 상태, 로컬 저장, 텍스트 공유를 구현하고 있다.

그러나 실제 사용자 인터뷰, 최소 5명 사용성 테스트, 계측된 유지율, 광고 이해도, 친구 도전 수요가 없다. 따라서 다음은 모두 **검증 대상 가설**이다.

- 한국 지하철 소재가 설치와 첫 3초 이해에 유리하다.
- 5×7 보드와 좌우 선택기 조합이 운이 아니라 실력으로 인식된다.
- 쉬운 초반과 안전 손잡이가 첫 실패 이탈을 줄인다.
- 실패 시 선택형 구조 광고가 강제성 없이 수용된다.
- 같은 시드 친구 도전이 일반 결과 공유보다 재방문을 높인다.

Product/UX Gate는 현재 **Fail**이다. 최소 5명 사용성 테스트와 핵심 P1 해소 전에는 Solution Definition 또는 Build Readiness 통과로 해석하지 않는다.

## 2. Brief

### 문제 가설

짧은 이동·대기 시간에 복잡한 학습이나 계정 생성 없이 즐길 수 있으면서도, 한 판의 실력 차이와 다시 도전할 이유가 분명한 세로형 게임에 미충족 수요가 있다.

이 문제의 빈도·강도·현재 대안은 아직 사용자 인터뷰로 검증되지 않았다. `Block Blast`, 정렬 퍼즐, 숏폼 콘텐츠, SNS, 기존 방치형 게임이 직접·간접 대안이라는 가설만 존재한다.

### 초기 대상 가설

- 한국 iPhone 사용자
- 통근·통학·대기 중 1~10분 단위로 모바일 콘텐츠를 소비하는 사람
- 복잡한 RPG 성장 구조보다 즉시 이해되는 퍼즐을 선호하는 사람
- 경쟁을 원하지만 실시간 멀티플레이 부담은 피하고 싶은 사람

연령, 성별, 결제 성향은 현재 미확인이다. 인터뷰 전 특정 페르소나를 사실로 고정하지 않는다.

### JTBD 가설

> 짧게 시간이 비었을 때, 설명을 읽거나 팀을 구하지 않고 바로 시작해 내 실력이 늘었다는 느낌을 받고 싶다.

### 네이티브 앱 가설

햅틱, 오프라인 즉시 실행, Game Center, 시스템 공유, 상태 저장이 웹보다 나은 경험을 제공한다. Game Center와 완전한 같은-시드 딥링크가 없는 현재 빌드는 이 가설을 아직 충분히 입증하지 못한다.

## 4. 목표와 비목표

### 검증 목표

1. 첫 사용자 4/5 이상이 외부 설명 없이 60초 이내 첫 승객을 배치한다.
2. 4/5 이상이 90초 이내 같은 배지 3명 연결 규칙을 말로 설명한다.
3. 첫 실패 후 4/5 이상이 강요받았다고 느끼지 않고 재도전 또는 종료를 선택한다.
4. 광고 보상과 거절 결과를 5/5가 정확히 이해한다.
5. 계측 가능한 베타에서 첫 판→두 번째 판 65% 중단선을 넘는다.

### 비목표

- App Store 1위 보장
- 실제 지하철 기관·노선·상표 복제
- 실시간 멀티플레이
- 확률형 상품 또는 성능형 유료 아이템
- 광고 설치·평점·리뷰 보상
- 계정 생성 강제
- 검증 전 시즌 패스, 대규모 수집, 서버 추천 시스템

## 7. 요구사항

### P0 — 검증 빌드 필수

- 게스트로 즉시 시작할 수 있다.
- 앱 수명주기 전환 시 게임 시간이 부당하게 흐르지 않는다.
- 같은 규칙과 시드로 재현 가능한 승객 순서를 만든다.
- 진행 저장 실패가 기존 최고 점수·스테이지를 파괴하지 않는다.
- 광고 보상은 성공 callback을 한 번 받은 경우에만 한 번 지급한다.
- 광고를 거절해도 새 판을 즉시 무료로 시작할 수 있다.
- 광고·분석 SDK를 넣기 전 개인정보·연령 등급·데이터 흐름을 재검토한다.

### P1 — UX/Product Gate 필수

- 첫 5명 사용성 테스트를 완료하고 결과를 문서화한다.
- 성공·실패·일시정지·광고 불가·오프라인·공유 불가 상태 문구를 검증한다.
- 친구 기능이 텍스트 공유이면 `같은 막차`라고 주장하지 않는다.
- 결과 화면의 역 번호를 실제 값으로 표시한다.
- 효과음이 없다면 효과음 토글을 숨기거나 `준비 중`으로 명확히 표시한다.
- VoiceOver, Larger Text, Reduce Motion 지원 여부를 실제 동작 기준으로 표시한다.
- 핵심 이벤트 정의와 데이터 품질 검증을 완료한다.

### P2 — 검증 후 후보

- Game Center 최신 점수 기반 도전
- Universal Link/App Clip
- 결과 이미지와 6초 리플레이
- 비성능형 꾸미기
- 실제 보상형 광고 SDK

## 8. 상태와 예외

필수 상태는 `첫 실행`, `홈`, `튜토리얼`, `플레이`, `일시정지`, `안전 손잡이 복구`, `구조 제안`, `광고 로딩`, `광고 거절`, `광고 실패`, `결과`, `공유 불가`, `오프라인`이다.

- 백그라운드 진입: 자동 일시정지, 복귀 시 명시적 재개.
- 광고 불가: 광고 CTA를 숨기거나 비활성 이유 표시. 유료/광고 없이는 새 판을 막지 않는다.
- 저장 디코딩 실패: 신규 프로필로 복구하되 오류를 로깅하고 원본 덮어쓰기 정책을 별도 결정한다.
- 시스템 시간 변경: 일일 도전 결과의 신뢰성 위험으로 기록하고 서버 도입 전 경쟁 보상을 주지 않는다.
- 네트워크 없음: 코어 플레이·로컬 진행은 유지하고 온라인 도전만 설명과 함께 제한한다.

## 9. 다크패턴·정책 원칙

- 강제 전면 광고, 가짜 닫기 버튼, 위장 CTA, 허위 카운트다운을 사용하지 않는다.
- 광고 버튼에 `광고 1회`, 정확한 보상, 소요 범주를 표시한다.
- 거절 버튼을 숨기거나 현저히 낮은 대비로 만들지 않는다.
- 평점, 리뷰, 타 앱 설치, 연락처 제공을 게임 기능·목숨과 교환하지 않는다.
- 친구 설치가 아니라 실제 도전 완료 후 양쪽에 같은 비성능형 보상을 주는 안만 실험 후보로 둔다.
- 부활 기록은 공식 경쟁에서 분리하거나 명확히 표기한다.
- 실제 광고 SDK는 연령 등급에 맞는 소재, 닫기/건너뛰기, 부적절 광고 신고 기능을 검증해야 한다.

## 10. Content & Localization

- 기본 언어는 `ko-KR`; 모든 사용자 문구는 Strings Catalog로 이동하는 것을 목표로 한다.
- 실제 교통기관 이름, 로고, 노선 번호를 사용하지 않는다.
- 실패 문구는 비난보다 원인과 다음 행동을 설명한다.
- `무료`, `광고`, `구조`, `기록 제외`를 완곡어로 숨기지 않는다.
- 한국어 숫자는 점수에 천 단위 구분을 사용하고, 시간은 `초`, 인원은 `명`으로 표시한다.
- 영어 등 다음 언어에서는 직역 전에 `만원열차`, `환승`, `안전 손잡이`의 문화적 이해도를 별도 테스트한다.
