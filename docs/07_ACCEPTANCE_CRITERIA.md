# 07. Acceptance Criteria

## A. 디자인 시스템

- [ ] 모든 색상은 디자인 토큰에서 참조한다.
- [ ] 타이포그래피, 간격, 반경, 글로우, 모션 토큰이 런타임에 연결되어 있다.
- [ ] Design System Gallery에서 주요 UI 상태를 한 화면에 볼 수 있다.
- [ ] 속성은 색뿐 아니라 아이콘, 궤적, 임팩트 형태로 구분된다.
- [ ] 레퍼런스 이미지 없이도 문서와 토큰만으로 재구현 가능하다.

## B. 플레이 가능성

- [ ] 터치, 마우스, 키보드로 패들을 조작할 수 있다.
- [ ] 공이 고속에서도 벽돌을 통과하지 않는다.
- [ ] 패들 충돌 위치에 따라 반사각이 달라진다.
- [ ] 공이 수평 루프에 빠지지 않도록 최소 수직 성분이 보장된다.
- [ ] 점수, 콤보, 생명, 스테이지가 정상 갱신된다.

## C. 효과

- [ ] Fire burn이 tick과 stack 규칙대로 작동한다.
- [ ] Electric이 유효한 가까운 타깃에 중복 없이 체인된다.
- [ ] Piercing이 charge만큼 반사 없이 통과한다.
- [ ] Explosion이 거리 감쇠와 연쇄 상한을 지킨다.
- [ ] Multi Ball이 최대 활성 공 상한을 지킨다.
- [ ] Ice가 Brittle 상태와 다음 타격 보너스를 적용한다.
- [ ] Homing이 제한된 각속도로 회전한다.
- [ ] Laser가 패들에서 일정 주기로 발사된다.
- [ ] Shield가 charge를 소모해 바닥 낙하를 방지한다.
- [ ] Slow Time이 게임 시간과 UI 시간을 분리한다.

## D. 가독성과 손맛

- [ ] 일반 충돌에 local impact, 짧은 squash, 사운드가 있다.
- [ ] 큰 충돌만 screen shake와 zoom을 사용한다.
- [ ] 동시 효과가 많아도 공의 위치를 추적할 수 있다.
- [ ] 콤보 단계에 따라 연출이 상승하되 화면을 가리지 않는다.
- [ ] 5개 이상 동시 데미지 숫자는 합산된다.

## E. 접근성

- [ ] Reduce Motion이 shake, zoom, trail, parallax를 줄인다.
- [ ] Photosensitivity Safe Mode가 전면 플래시와 강한 점멸을 제거한다.
- [ ] Color Assist가 각 속성에 문양과 아이콘을 제공한다.
- [ ] High Contrast Ball 옵션이 있다.
- [ ] 키보드 focus 상태가 보인다.

## F. 성능

- [ ] 파티클과 임시 오브젝트가 풀링되어 있다.
- [ ] Effect Lab 스트레스 테스트에서 예외가 없다.
- [ ] 활성 공 8개와 복합 효과에서 성능 오버레이가 동작한다.
- [ ] 브라우저 탭 복귀 후 delta 폭주가 없다.
- [ ] Low FX가 파티클과 배경 부하를 실제로 낮춘다.

## G. 코드 품질

- [ ] TypeScript strict mode를 통과한다.
- [ ] 효과 등록이 데이터 주도 구조다.
- [ ] 핵심 수치가 하드코딩되지 않았다.
- [ ] 단위 테스트가 효과 적용, 해제, 중첩, 만료를 포함한다.
- [ ] README에 실행, 테스트, 빌드 명령이 있다.
